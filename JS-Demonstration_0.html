Six cases taillées à l'avance. On se contente d'allumer la bonne.

/* un état = quatre règles, à recopier pour chaque nombre */
#s1:checked ~ .readout .v0 { display: none; }
#s1:checked ~ .readout .v1 { display: block; }
#s1:checked ~ .k1 { display: none; }
#s1:checked ~ .k2 { display: block; }
/* … puis on recommence pour 2, 3, 4, 5, 6, 7 … */

Ça compte — mais rien n'a été calculé. Les nombres 0 à 5 sont écrits en dur dans le HTML ; le CSS les montre et les cache. Il ignore que 2 vient après 1. Il ne connaît même pas la notion de « suivant ».

Une seule case. Son contenu change tout seul.

let n = 0;

bouton.addEventListener('click', () => {
  n = n + 1;
  valeur.textContent = n;
});

Trois lignes. Le nombre 5000 n'est écrit nulle part dans ce fichier, et pourtant on peut y arriver. C'est la différence : une valeur en mémoire, et une opération dessus.

Les trois questions à poser une fois que tout le monde a cliqué

Elles vont crescendo. La troisième est celle qui compte vraiment.

  1. « Faites-moi compter jusqu'à 1000. »

    JS : on ne touche à rien, c'est déjà le cas. CSS : environ 4000 lignes à écrire.

  2. « Ajoutez-moi un bouton −1. »

    JS : n = n − 1, une ligne. CSS : il faut refaire toute la machinerie en sens inverse.

  3. « Affichez "beaucoup" au-delà de 10. »

    JS : if (n > 10). CSS : impossible. Aucune comparaison n'existe dans le langage.

Le CSS peut montrer un résultat préparé à l'avance.
Le JavaScript peut produire un résultat qu'on n'avait pas prévu.
